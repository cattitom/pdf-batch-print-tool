# 2026-11-02 桌面端「双击打不开、会卡住」问题

## 现象
用户双击 `C:\Users\Administrator\Desktop\PdfBatchPrint.lnk`：窗口不出来，或者出来就白屏/未响应，
任务管理器里 `desktop.exe` 状态是「无响应」。AppHangTransient 事件也能对上。

## 根因（两条叠在一起）
1. `commands/kdocs.rs` 的 `sync_kdocs_packing` 是**非 async** 的 `#[tauri::command]`。
   Tauri 的同步命令跑在主线程（消息循环）上，里面又 `spawn_bounded("node", …kdocs-pull.mjs…)`
   等最长 120 秒 → 整个窗口在这段时间里完全无响应。
2. 前端 `PackingPage.tsx:904` 一进「出货清单」就后台同步，所以**每次启动必卡**；10 分钟定时器还会再卡一次。
   而 `kdocs-pull.mjs` 每次都要空等 45 秒（90×500ms 轮询 CDP 端口 9333）才放弃，所以卡得很稳定。

## 为什么取数脚本一定失败
`kdocs-pull.mjs` / `kdocs-login.bat` 里 Chrome 路径只写死了
`C:\Program Files\Google\Chrome\Application\chrome.exe`（和 x86 那个）。
这台机器 Chrome 是**仅为当前用户安装**：`%LOCALAPPDATA%\Google\Chrome\Application\chrome.exe`，
于是无界面 Chrome 从来起不来，每次同步都白等 45 秒后以退出码 3 失败，而且 RUST 侧失败路径没打日志
（app.log 只有「云表格同步：开始拉取」，后面一片空白）。

## 已改（3 个文件，未提交）
- `desktop/src-tauri/src/commands/kdocs.rs`
  - `sync_kdocs_packing` 改 `pub async fn`，真正干活的是新增的 `fn sync_kdocs_packing_blocking(...)`，
    用 `tauri::async_runtime::spawn_blocking` 丢到阻塞线程池 → 主线程不再被占。
  - 所有失败路径补 `log::warn!`（含耗时 ms / stderr / 解析报错），成功日志也带耗时。
- `tools/kdocs/kdocs-pull.mjs`
  - `CHROME_CANDIDATES`：`KDOCS_CHROME` → Program Files → Program Files (x86) → `%LOCALAPPDATA%`，
    取第一个 `existsSync` 的。
  - 起无界面 Chrome 前先 `existsSync(CHROME)`，没有就立刻 `exit(3)` 并列出找过的路径（不再空等 45 秒）。
  - CDP 轮询 90 次 → 40 次（最多 20 秒）。
- `kdocs-login.bat`：同样补 `%LOCALAPPDATA%` 候选（原来在这台机器上直接跳到 nochrome）。

## 验证
- 双击快捷方式：窗口 0.25–0.41 秒出来，连续采样 8–10 秒 `Responding` 全为 True（改之前必挂）。
- app.log 现在写：
  `云表格同步：开始拉取` → `WARN 云表格同步失败（2654 ms）：WPS 云表格没登录（下载接口 HTTP 403）。…`
- 已替换安装目录 `C:\Users\Administrator\AppData\Local\PdfBatchPrint\desktop.exe`
  （旧版备份 `desktop.exe.bak-20261102-183201`），NSIS 安装包也重新出了：
  `src-tauri/target/release/bundle/nsis/PdfBatchPrint_0.1.0_x64-setup.exe`。

## 还剩下的（不是 bug，是环境）
云表格同步本身仍取不到数：`%LOCALAPPDATA%\kdocs-cdp-profile` 里没有 WPS 登录态（下载接口 403）。
要真正同步，得双击项目根目录的 `kdocs-login.bat`，扫码登录并让那个 Chrome 窗口一直开着，再点「从云表格同步」。

## 教训
- Tauri 里任何会跑外部进程 / 长耗时 IO 的 command 都必须 `async` + `spawn_blocking`，否则就是「窗口卡死」。
- 直接 `cargo build --release` **不是**能用的安装包：没开 `tauri/custom-protocol`，
  前端会去连 `http://localhost:1420`（devUrl），装上去就是「无法访问此页面」。出包只用 `pnpm tauri build`。
