## 0. 测试前准备

1. 保存正在处理的内容，关闭已有桌面程序。
2. 复制 `%APPDATA%\com.hanlin.pdfprint` 整个目录做备份，尤其是 `pdf-tool.db`；不要手动删除数据库、历史记录或出货记录。
3. 云同步需要 Node.js 22.12.0+，本机已验证版本为 24.12.0；手机和电脑需连接同一个 Wi-Fi。
4. 首轮尽量用下面的样例，不用正在出货的真实单据做并发试验。

## 1. 安装、启动（必须先通过）

1. 双击上面的安装包；已有版本时选择安装／重新安装。
2. 确认安装目录，完成安装后启动程序。
3. 检查 PDF 拼版、出货清单、设置页面能打开。
4. 检查安装目录 `models/` 中有检测模型、识别模型及字典：
   - `PP-OCRv6_medium_det.mnn`
   - `PP-OCRv6_small_rec.mnn`
   - `ppocr_keys_v6_small.txt`

**预期：** 正常进入主界面，没有闪退、白屏、数据库只读或打不开数据库错误。

**如果失败：** 停止后续测试，记录启动方式、安装目录和错误原文；如能进入设置，打开日志目录；否则查看 `%APPDATA%\com.hanlin.pdfprint\logs\app.log`。不要先删除数据库或大范围修改系统权限。

## 2. PDF 拼版、预览和防覆盖

1. 导入 `CROP-A4-3页.pdf`，目标页数设为 4，旋转 90°，启用自动裁剪。
2. 再导入 `PROBE-A4.pdf`，目标页数设为 2。
3. 每页份数设为 1，文件间分隔页设为 1，启用页码。
4. 生成到测试输出目录，打开成品并逐页检查。
5. 使用相同输出名称再生成一次，检查第一次成品。

**预期：** 共 7 页；顺序正确，首份旋转及裁剪正常，分隔页和页码可见；重复生成自动改名，不覆盖第一次输出和源文件。

## 3. 原始旋转、继承属性和批注

1. 用 PDF 阅读器分别打开新增的四个 `继承属性_原始旋转*_含批注.pdf`，记住原始显示方向。
2. 在工具里逐个导入，追加旋转设为 0，不裁剪，各输出一页。
3. 对比原文件和输出文件的文字、蓝色矩形、方向及页面尺寸。
4. 再任选一个文件追加旋转 90°，确认是在原始方向上继续旋转。

**预期：** 不丢文字／图形，原始方向保留，批注反向引用不造成卡死或闪退。该测试不要求交互批注坐标在旋转后完全保留，通用批注变换不在本轮修复范围。

## 4. 表格导入和出货记录

1. 在出货清单中导入 `装箱单样例.xlsx`。
2. 核对商品、数量、单号和入库号，检查标黄提示。
3. 勾选一条带单号或入库号的记录，再选几条进行批量标记。
4. 等“保存中”提示结束，完全关闭程序后重新打开同一份表。
5. 找一条单号和入库号都为空的行，确认不能标成已出。

**预期：** 单行及批量状态能恢复；无标识行被阻止。若出现保存失败，应有明确原因、重试和放弃入口，界面不能静默显示成功。

不要通过改数据库权限、锁生产数据库等方式主动制造失败；故障注入留给自动化隔离测试。

## 5. PaddleOCR

依次导入三张样例截图：

| 文件 | 核对值 |
|---|---|
| `装箱单样例.png` | 12 行，168 件，单号 6812704625 |
| `装箱单样例2.png` | 7 行，66 件 |
| `装箱单样例3.png` | 合计 128 件，至少 21 条有效行 |

**预期：** 界面标明 PaddleOCR；没有 Windows 系统 OCR 选项；仍需核对原图和标黄行。

可选缺模型检查：仅对独立解压的便携包进行，关闭程序后将该副本的 `models` 改名，重开并导入截图。
**预期：** 明确提示缺少 PaddleOCR 模型；不偷偷调用系统 OCR；PDF 信息与表格导入仍可用。完成后恢复该副本的 `models` 名称。不要移动正式安装目录或源码目录中的模型。

## 6. 标签与历史

1. 如需箱唛功能，在设置中开启对应入口，用测试单号生成预览。
2. 检查文字、条码和二维码是否可见；可用手机普通扫码功能核对内容。
3. 检查刚生成 PDF 的历史记录，重启后再次查看。

**预期：** 预览正常、历史能恢复。不要清空已有业务历史。

## 7. WPS 云同步

1. 在出货清单中登录 WPS，手动同步，明确选择一张工作表。
2. 等待后台检查（约 10 分钟），确认选择的表名不跳到其他月份。
3. 在确认不会影响业务的测试表中产生新版本，先选择暂不更新。
4. 检查当前表名、内容和勾选状态没有变化；关闭、重启后仍恢复上次确认的数据。
5. 点击“换最新”，核对应用的是提示的那张表及新版本。
6. 导入本地文件后等待后台检查，确认云更新不会替换正在看的本地文件。

**预期：** 当前数据与待更新数据分开；用户确认后才替换；重启不会加载未确认的新版本。

如无法安全修改云端测试表，只测登录、同步及保持选表，其余项目标“未测”，不要修改真实业务表凑测试。

## 8. 手机配对、双端操作和保存

1. 桌面打开手机出货，手机首次扫描电脑二维码；旧链接失效时重新扫码。
2. 手机打开一票，勾选一行，确认保存结束；桌面应随后显示对应状态。
3. 手机再勾选一行，保存成功后立即关闭桌面程序，再启动并打开同一份表。
4. 用另一台手机或电脑浏览器打开同一票，尝试基于旧页面状态修改同一行。
5. 桌面换到另一份表，再从旧手机页面提交，确认会提示刷新核对。
6. 桌面更换口令，确认旧链接不再能读取清单或修改状态。

**预期：** 手机保存成功即已落库；重启恢复；旧版本和旧表请求被拒绝，不能静默覆盖其他设备状态；首次发现电脑不等于获准访问，仍需扫码。

手机短暂断网时，不能把“未收到保存结果”当作成功；恢复连接后先刷新核对，避免重复操作。

## 9. 真实打印

1. 用测试生成的 PDF 打印 1～2 页，核对方向、裁剪、内容是否完整。
2. 如使用热敏标签，单独核对标签纸尺寸与打印机设置。
3. 确认小批量正常后再试多份，避免一开始输出大量纸张。

**预期：** 阅读器显示与纸面一致，旋转和裁剪不导致内容丢失。
